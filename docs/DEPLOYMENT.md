# Deployment guide

## 1. Prepare the Proxmox LXC

On the Proxmox host:

```bash
cd lxc
cp lxc.env.example lxc.env
nano lxc.env
sudo ./scripts/deploy-proxmox.sh
```

The deployment script creates a Debian LXC, installs Python, FFmpeg, FastAPI and `faster-whisper`, then starts `voice-notes-api.service`.

Check the service from inside the container:

```bash
systemctl status voice-notes-api
journalctl -u voice-notes-api -f
```

Test from another machine:

```bash
cd lxc
./scripts/test-api.sh http://LXC_IP:8080 API_TOKEN sample.wav
```

## 2. Configure the firmware

```bash
cd firmware
cp include/secrets.example.h include/secrets.h
nano include/secrets.h
```

Set:

- Home Wi-Fi SSID and password.
- iPhone hotspot SSID and password.
- API base URL.
- API Bearer token generated by the LXC installer.

Home Wi-Fi has priority over the iPhone hotspot.

## 3. Build and flash

With PlatformIO installed:

```bash
cd firmware
./scripts/build.sh
./scripts/flash.sh
./scripts/monitor.sh
```

Or directly:

```bash
pio run
pio run -t upload
pio device monitor
```

## 4. First hardware validation

Before the first end-to-end recording, validate `include/board_pins.h` against the exact Waveshare ESP32-S3-ePaper-1.54 V2 hardware revision.

Recommended order:

1. ePaper boot screen.
2. SD mount and directory creation.
3. Button events.
4. ES8311 microphone capture.
5. WAV playback/check on a PC.
6. Home Wi-Fi.
7. iPhone hotspot.
8. API health endpoint.
9. One complete note upload/transcription/download cycle.
10. Offline queue then reconnect and sync.

## 5. Data-safety behavior

The SD card is authoritative for unsynchronized audio:

- Audio is first written to `/audio/recording/current.tmp`.
- A completed recording is atomically moved to `/audio/pending/<note_id>.wav`.
- Upload retries keep the pending WAV untouched.
- The server request is idempotent by `note_id` and SHA-256.
- The ESP writes the Markdown transcript before archiving the WAV.
- Only after a successful local transcript write is the WAV moved to `/audio/archive/`.
